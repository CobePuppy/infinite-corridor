# 设计访谈与试玩

## 把一句偏好问成一个可执行的决定

1. **先取样。** 用已知信息复述一段游玩情境，请用户指出具体时刻。「你说冲刺不跟手，最近一次是按下后起步慢，还是松开后越过了落点？」能直接查到的输入配置或时序由 Agent 自查。
2. **让差异可感知。** 针对最大的分歧给两种有实际差别的方案。说清玩家按同一个键会看到什么、会牺牲什么，可以附建议及理由。留出自定义答案。用户表达不清时用一张草图、两段操作描述或一个小实验继续收敛。
3. **追问答案会改变的那一点。** 把选择复述为「在这个局面做这个动作，应发生什么」，用反例检验解释。若答案已经明确，直接落实。讨论到上下游取舍时，把不同人的判断及其理由原样区分，交给当前有决定权的人。
4. **把决定写回。** 在对应玩法条目、计划或任务中写定已裁定的行为、被舍弃的方案及验证方法。仍未知的值写成带验证方法的假设。用户愿意比较后再决定时，交付能区分选项的最小实验，并约定看什么结果再定。

**一段示例对话**

> 玩家说「钩索要更自由」。
>
> Agent 问「你最想做成哪个动作：松手借惯性飞过沟，还是在空中换一个锚点？前者考松手时机，后者考瞄准。也可以描述你脑中的一跳。」
>
> 用户答「松手飞过沟，但新手别总撞墙。」
>
> Agent 再问「快撞墙时你希望游戏自动减速，还是保持速度、用落点提示帮人提前松手？自动减速会改变同一跳的飞行距离。」
>
> 用户答「速度保留，先试提示。」
>
> 此时写入玩法规格的是「松手保留惯性」。写入原型卡的是「落点提示可能帮助新手」。两版使用同一段沟、同一套运动参数，由实际试玩决定是否保留提示。

## 用试玩回答体验问题

**开玩前**写定构建、设备、玩家背景、同一段可重复的任务和观察方法。验收条件取自本轮目标。涉及比例、时间或帧率时说明基线、目标、单位和适用设备；缺少依据就先记录实测。A/B 比较尽量只改一个变量，必要时交换游玩顺序。

**试玩中**给目标，留出玩家自己发现方法的机会。记下关键输入、视听反馈、重试或放弃发生在哪。先问「刚才你以为会发生什么」，再问偏好。把介入提示和时机记在观察旁，避免把提示后的成功算作自行学会。

**试玩后**按下列字段留下能复核的一条记录。同一设备的脚本回放可以验证规则或复现缺陷。关于好不好控、看不看得懂的结论要注明实际玩家及观察范围。没人试玩时交付可操作的试玩任务，体验项保持待验证。

| 构建与场景 | 来源与观察 | 对应的判断 | 决定与下一步 |
| --- | --- | --- | --- |
| 示例：原型 B，手柄，练习沟，开启落点提示 | 一名首次游玩的玩家在第二次起跳前移动准星，说「我想让线落到对面」；第一次失败后主持人未提示 | 该玩家注意到了落点。一次观察还不足以确认提示能降低撞墙次数 | 保留为待验证假设。用相同运动参数比较有无提示两版，记录首次越沟前的撞墙次数 |

**回到能解决问题的阶段。** 实现偏离规则，返回制作并重跑失败用例；规则不同解释都成立，回到玩法澄清补边界例；规则按预期运行但体验目标落空，回到原型比较替代方案；成本超出切片计划，请负责人选削减范围、降低品质或调整时间，并更新对应验收条件。
