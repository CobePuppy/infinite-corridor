# 游戏项目协作流程

依据本轮制作人明确的 Step 1 → Step 2 → Step 3。工作区设计输入为原样同步的[随附设计稿](game_design_doc.md)。设计变更先同步基线。新增实现细节以【占位】或【待定】标记。目录、计划与外部操作约定见 [AGENTS.md](../AGENTS.md)。

## Step 1 · 五份核心文档

依次交付[项目计划书](01_项目计划书.md)、[玩法策划](02_玩法策划.md)、[技术栈](03_技术栈.md)、[美术设定集](04_美术设定集.md)、[文稿与日志](05_文稿与日志.md)。核查基础设计覆盖、文件完整、状态口径和可追溯性，然后进入交叉审核。

## Step 2 · 交叉审核与修订

按策划、开发、美术、测试顺序逐份检查。形成交叉审核意见，去重列出问题、严重程度、修订位置和复核证据。五份文档全部更新后验收。

## Step 3 · 会话启动、任务分配与验收

创建开发、美工、测试、策划和 Git 管理会话。根据项目计划书分配任务与验收口径，记录每项产物和证据。当前阶段仅启动会话并完成任务分配。M1 实作、构建、上传、试玩及 M2–M4 由后续指令启动。

## 目录和本地检查

docs/ 保存上述文档和验收。src/ 存源码，assets/ 存美术音频源件，memory/ 存工作记录，trash/ 存暂移文件，scripts/ 存自动检查，.agents/skills/ 提供通用参考。

在工作区根目录用 PowerShell 运行 ./scripts/Test-Workspace.ps1。脚本核对基础目录、文档与协作指南的本地链接。
