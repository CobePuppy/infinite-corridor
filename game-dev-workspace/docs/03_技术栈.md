## 1. 引擎与依赖

【已定】2D、单机单人。源设计主推 Unity/C#，备选 Godot 4.x/GDScript。【占位】M1 选 Unity 6.3 LTS 和 2D Renderer。现有设计需要 Sprite 图集、2D 判定、编辑器调参和帧分析，团队可用同一个工程跑灰盒、测试和 Windows 包。若本机或目标平台验证失败，再立项评估 Godot，复用地图拓扑、规则和测试向量。引擎及版本为建议，安装和实机验证【待定】。

| 依赖 | M1 候选版本和用途 |
| --- | --- |

## 3. 核心架构

| 系统 | 输入、状态与交付点 |
| --- | --- |
| 地图与房间 | RunSeed、楼层和生成器版本确定布局。图节点以 RoomId、网格坐标、类型、门集合和房间状态保存。使用独立 RNG 子流生成布局/刷怪/掉落，狭义门图用于移动，网格洪泛用于围住。验证连通、出生、Boss、房型数量和围住演示路线后固化种子 |
| 时钟与阶段 | RunFlow 管理 Preview、Explore、Boss、FloorTransition、Result。探索钟管理计时和建筑推进；战斗钟管理弹幕、状态和技能。全局暂停冻结两者；Boss 只运行战斗钟。HUD 消费时钟快照 |
| 战斗与弹幕 | DamageResolver 接收攻击方快照、防御、两类穿甲、命中规则，返回整数伤害、盾吸收、剩余 HP、控制状态。技能状态机驱动前摇、生效和冷却。ProjectilePool 按弹族预热；回收重置归属、命中状态、寿命、速度、表现，切房清理。高速弹用从上一位置到当前位置的扫掠 |
| 建造与经济 | Wallet 统一处理带原因的资源事务。以 RunId+RoomId 标记建筑位，状态为未建造、已完成等级、生产剩余毫秒；矿场通过整局唯一键校验。产出、扣费、升级与刷新状态作为一次提交，远程请求不绕过余额或时钟 |
| 存档与科技树 | Profile schemaVersion、oreBalance、已应用 RunId、已解锁 ID 和设置。本局状态独立内存；结算把矿石和已应用 RunId 写入同一版本档案。写临时文件→验证→替换并保留上一份可读备份，失败显式可重试。读取时按版本迁移并保留备份，科技节点校验余额、前置和已解锁状态。M1 节点只读 |

【占位】一个更新步先提交角色死亡，再提交 Boss 死亡和奖励；当步从探索钟扣到 0 时，超时转换优先于常规传送落点。输入只可申请一次转换，用 RunId + 转换版本去重。档案遇保存失败保留待提交金额与同一 RunId，确认重试后只加一次。显示到账以成功回执为准。M1 支持存档失败时在本次会话重试，应用在成功写入前退出时未到账金额的恢复支持【待定】。

结算事件最少含 RunId、Floor、RoomId、来源、变动和状态版本。房间状态和奖励更新后发事件，UI 统一订阅，拒绝重复操作时显示原因。数据与美术索引对照[美术设定集](04_美术设定集.md)及[文案键](05_文稿与日志.md)。

## 4. 性能与运行验证

- 【占位】Windows x64、1920×1080，目标 60 FPS。单房同屏预算 32 敌人、384 个有效弹体、64 个视觉短特效、120 个 DrawCall。标注硬件后再校准。
- 使用 Unity ObjectPool 或等价池。按 8 发/24 发弹族分池并按压力测试预热，容许扩容至有效弹体预算。关键招式在起手前预留完整弹量；余量不足就等回收再起手，具体延迟记录成回归指标。视觉池饱和只舍弃非判定粒子。避免每发弹或每帧产生临时集合。渲染共用材质、Sprite Atlas 和排序层，限制透明全屏和动态光。特效与碰撞逻辑分离。
- 用同一已知种子复现 4 发连珠、16 发环射、狂暴和弹量压力。记录 Unity Profiler 的 CPU、GPU、GC、Frame Debugger 批次、对象池峰值、关键弹缺失数与等待创建次数。正式构建关闭调试绘制；同种子在独立进程预热后采样 60 秒，帧时 P95 ≤17 毫秒、有效弹缺失 0 为【占位】门槛。记录 CPU/GPU、驱动和构建 SHA。
- EditMode 核验地图、围住、整型伤害、事务和存档迁移；PlayMode 覆盖键位、房间切换、强制 Boss、双能量、对象池复用和结算场景。开工后补实测命令、Unity 日志和构建编号。当前工作区暂无 Unity 工程【待定】。
