# 项目计划书

版本 v1.1 · 2026-11-20 · Step 2 修订  
设计依据为[游戏企划与设计总结 Demo v1](game_design_doc.md)。项目名称【待定】。

## 1. 定位与卖点

【已定】一款围棋与古风主题的单机单人俯视角 2D 弹幕射击肉鸽。玩家提唐刀在棋盘关城中开路，围出机会，再用沿途建起的建筑为迎战棋帅备战。

【已定】每局在探索时限内清房、攒钱、投资源。围住未探房间后，玩家在花钱快速拿常规奖励和亲自迎战争取稀有掉落之间选择。商场、建材厂、矿场和村庄提供不同收益，和当前战力、时间、局外成长争夺同一份建材。评委应能在一次短演示中看懂“围住一次、建成一处、打到 Boss”的因果链。目标玩家是核心动作和肉鸽玩家。

## 3. 范围

- 【已定】M1 做一层、角色一完整动作和双能量大招、5 种普通/精英敌人与镇关棋帅、网格探索和围住分支、资源与村庄建筑、普通结算和死亡结算。商人保留高利贷和购买建材的最小交互，科技树提供界面及矿石余额，实际节点效果后置。
- 【已定】事件房、村庄事件、完整道具池、正式美术均可后置。M1 使用灰盒、占位强化和一条矿石存档验证路径。
- 【已定】完整版按 3 层、每层约 15 房设计。新增角色、新地图、多结局和商人破坏特殊事件在后续单独立项。联机、付费系统、移植和正式发行【待定】。

## 4. 里程碑与交付

| ID | 目标 | 交付物与可观察验收 |
| --- | --- | --- |
| M1-A | 走通一层 | 灰盒包和固定种子。可预览、移动、冲刺、清房、传送，在地图辨认围住并亲自挑战或付费自动探索 |
| M1-B | 闭合资源与大招 | 清怪金币、初始建材、商人借贷及负金币恢复、四类建筑通过至少两局覆盖。村庄累积氛围，战斗命中积攒战斗值，两条满后可开大，显示扣血、临时血条及攻击增益 |
| M1-C | 完成战斗与结算 | 五类敌人和镇关棋帅有可复现的预警；能正常进 Boss 和超时进 Boss。胜负均进结算，局内资产清零，矿石重启可读且只入账一次。附复现步骤和性能记录 |
| M2 | 三层闭环 | 连通三层的试玩包。跨层计时增益、商场衰减、村庄叠加、矿场唯一性及科技树基础节点效果均有确定样例 |
| M3 | 代表性内容与品质 | 一段含正式角色、房间、Boss、UI 和音画反馈的切片。逐条核对预警、可读性、资源导入和同屏性能，提交真人试玩记录 |
| M4 | 竞赛候选 | 可复现构建、演示流程、素材清单、兼容与回归结果。候选包、实际提交及公开发布分别记录授权和回执 |

固定种子、状态及键位见[玩法策划](02_玩法策划.md)。性能目标见[技术栈](03_技术栈.md)。

## 5. 人员与责任

| 角色 | 职责 | 交付 |
| --- | --- | --- |
| 制作人兼游戏总监 | 排优先级、确认规则和跨职能取舍、分配任务、验收 | 里程碑状态和返工决定 |
| 开发 | 地图、战斗、建造、界面、存档与打包 | 可运行构建、代码位置、命令、实测 |
| 美工 | 灰盒提示、角色敌人、场景、HUD 和导入样例 | 源件、导出、素材表和实机证据 |
| 测试 | 功能、边界、存档和性能测试，组织后续试玩 | 用例、预期、实际、构建与复现步骤 |
| 策划 | 维护规则和数值，接收测试证据，记录变更 | 配置单、验收样例、设计基线版本 |
| Git 管理 | 分支、提交、锁文件、版本与远端交付 | 本地提交基线和发布清单，外部动作经授权 |

【占位】同一人可兼任多个角色。总监对交付物按上表独立验收。

## 6. 开发时间表与风险

【占位】从授权开工日 T 起按工作日估算。首个可玩 M1 第 1–10 个工作日，T+1–3 做地图与输入，T+4–7 做战斗和经济，T+8–10 串联 Boss、结算和回归。M2 第 11–17 天，M3 第 18–28 天，M4 第 29–35 天。美术灰盒、规则核算、测试用例可在同一里程碑并行。工期根据实际人力、竞赛截止日和 M1 实测重估。

| 风险 | 影响 | 检查与处理 | 责任 |
| --- | --- | --- | --- |
| 围住触发太少或误判 | 核心卖点延后 | 固定围住图、边界图与多个随机种子分别验收 | 策划 / 开发 |
| 建材开局选择卡死经济 | 无法验证村庄、大招或矿场 | 验证买料、贷款、工厂、负数恢复与早建矿场 | 策划 / 测试 |
| Boss 过硬或预警难读 | 首轮试玩中断 | 测不同强化路线、普通/狂暴招式及前摇辨识 | 测试 / 美工 |
| 弹幕峰值卡顿 | 不公平死亡 | 设备上记录帧时间、图集批次、对象池峰值 | 开发 |
| 三层和美术赶不上 | 竞赛包不可控 | 先提交候选范围，再按 M1 到 M4 的实际证据决策 | 总监 |
| 存档重复入账、素材授权缺失 | 成长失真或交付受阻 | 用同一局 ID 重试结算。素材登记来源与许可 | 开发 / Git 管理 |

## 7. 里程碑验收方式

【占位】M1 按 [可复现用例](02_玩法策划.md#8-灰盒验收用例)核对。两局走不同建材起手，并额外走一遍死亡、超时和保存失败复试。保存种子、配置版本、构建 SHA、操作路径、预期与实测。M1-A/B/C 均有结果且保存错误可恢复，才标为通过。任何实测缺项标【待定】。

Windows x64 是当前开发包目标，比赛入口仍待规则确认。GitHub 代码协作与试玩包分发都等授权。当前阶段仅完成文档、审核与待执行任务派发，M1 实作和构建从 Step 4 启动。遇到计划偏差时，保留 M1-A/B/C，优先缩减正式画面、额外内容与后续层。
