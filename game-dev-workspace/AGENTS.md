# AGENTS.md — AI 工作手册

## 1. 我是谁
- 身份：独立游戏开发者（参赛选手）
- 主要业务：开发一款「俯视角 2D 弹幕射击肉鸽」独立游戏（围棋 + 古风主题，元气骑士式关卡设计），用于参加比赛
- 目标受众：游戏比赛评委、核心动作 / 肉鸽类玩家
- 项目代号 / 游戏名：[游戏名待定]

## 2. 输出要求
- 语言：简体中文
- 文风：直接、干脆、白话，不堆术语，不绕弯子
- 文件命名：`日期_主题_版本`，例：`0620_玩法策划_v1.md`
- 所有产出文件存到本项目对应子目录，不要散落在根目录
- 设计文档统一用【已定】/【占位】/【待定】标注内容状态

## 3. 目录约定
- `/docs` — 设计文档（项目计划书、玩法策划、技术栈、美术设定集、文稿日志、交叉审核意见）
- `/src` — 游戏源码
- `/assets` — 美术、音频、动画资源
- `/memory` — 工作记录、复盘笔记
- `/trash` — 删除文件的暂存处（不真正删除）
- 发现目录结构混乱时，先整理再开工

## 4. 工作原则
1. 接到任务先列计划，确认后再执行
2. 改文件前先说明要改什么、为什么
3. 任务完成后报告：生成/修改了哪些文件，放在哪里
4. 不确定的事直接问我，不要自己猜着做
5. 同一个错误不犯第二次：我纠正过的做法，记进本文件第 6 节

## 5. 安全红线
- 永远不删除文件，只移动到 `/trash` 目录
- 不碰本项目文件夹以外的任何文件
- 涉及发布、发送邮件、花钱、`git push` 上传仓库的操作，必须先经我确认

## 6. 我的偏好积累（持续更新）
- 数值一律向上取整，避免小数
- 伤害计算顺序：先算穿甲，再算攻防
- 报告先给结论，再给过程
- 基础设计输入以 `game_design_doc.md` 为准，改动设计需先同步该文档
- 开发流程按 `codex_workflow_instructions.md` 执行（Step1 → Step2 → Step3）
- 每批开发调整通过验收后，提交并推送到私有仓库 `yizhitao0512/2026-personl-game-program-yi`，再回读远端目标分支的完整提交 SHA 并与本地提交核对。此项已获授权，第 5 节对其他外部操作的确认约定照常执行。
