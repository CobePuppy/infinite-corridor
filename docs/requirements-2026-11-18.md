## 0. 先对齐术语：这份文档不是当前代码的直接 bug 清单

| 地图《回环》 | 词表里有房间名「**环室**」；房间 `shape` 枚举为 `arena / corridor / cross / chamber`，**没有「地图」实体** | 疑似指某类房间布局，按刷怪点问题处理 |

### 6.3 B1 残留缺陷已被队友补齐（重要）

第 2 节记录的本轮 B1 修复只做到「排除与墙重叠的坐标」。队友在《参赛改进与美术方向.md》

**无入口的四面墙圈内部** —— 该区域不与墙重叠、也过了中心禁区，旧校验会放行，但玩家永远
走不进去，导致清不掉场（死档）。

当前 `src/core/engine.js` 已由队友改为 **导航格可达性**方案：
`roomNavigation()` 按 24px 网格建图、`clearPath()` 校验格间连线、从玩家格 BFS 计算 `depth`；
`spawnValid()` 追加 `nearestNavCell(..., true) >= 0`（必须落在玩家可达区域）与敌间不重叠检查；
`spawnPoint()` 兜底改为从 `nav.points` 里挑 `depth >= 0` 的格点。
`tests/fullsuite.js` §A7 补了强制抽到封闭内角 `(581,393)` 的固定用例。

**总监独立复核（不采信自报数字）**：`verify-b1.cjs` 自行实现 20px 网格 BFS，抽样
**320 局 / 861 个敌人**，检查墙内 / 不可达 / 中心禁区 / 贴脸 / 敌间重叠五类缺陷，
结果 `{"wall":0,"unreachable":0,"center":0,"player":0,"overlap":0}` → **PASS**。
