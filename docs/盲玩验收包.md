## 2. 主持人手册

### 2.1 人数与轮换

- **6–8 名初次玩家**，此前没看过《参赛改进与美术方向.md》、没看过任何证据截图、没听过机制讲解。
- 主轮统一用 **「廊道回扫」** 入口，站位 `A / B` 各半（如 8 人则 4/4），
  **先跑 A 还是先跑 B 要在人与人之间交替**，避免顺序效应。
- 可选热身轮：**「单房试玩」**（版本 A/B × 重刃/手炮 × 预设 1/2），用来接住
  《单房自测记录.md》结尾的「真人待记」项。热身轮与主轮**分开记录、不混算**，
  且热身轮放在主轮**之后**（否则会教会让玩家「贴墙射击」，污染主轮）。

### 2.2 三条铁律

1. **不剧透**：只念交接卡上那一句提示，不解释「回扫」「折角」「词条」「炮台」，
   不说上廊短 / 下廊长 / 中廊有追兵。
2. **不提示**：试玩中玩家卡住、问「怎么打」、走错路，主持人只回答「按你觉得对的来」，
   不指路、不示范、不代操作。卡满 **3 分钟**记一次「卡住」并继续观察，不救场。
3. **先记录后看答案**：每人的记录表当场填完、录屏文件当场命名归档，
   **全部收齐之前**不要打开本文件第 8 节，也不要把数值 / 截图 / 定向结果给试玩者看。
   （《单房自测记录.md》原话：「完成记录后再看下方数值、截图和定向结果」。）

### 2.3 单场时间轴（建议 12–15 分钟 / 人）

| 阶段 | 时长 | 主持人动作 |
|---|---|---|
| 交接 | 1 min | 给交接卡，念一遍提示与按键，确认能打开 `index.html` |
| 静默试玩 | 6–8 min | **全程不说话**，只记时间与行为；录屏从进入房间开始 |
| 追问 | 2–3 min | 按交接卡三个开放式问题逐条问，**原话记录**，不引导、不纠正。若玩家没主动提到「有东西扫过去」，可追加一句中性追问：「刚才有没有注意到画面上有一段被点亮 / 扫过？它从哪边过来的？」——**只问现象，不解释机制、不说『回扫』二字**（对应 S1「指出波先走哪段」） |
| 定向场景（S3） | 2–3 min | 追问结束后，再请玩家按 2.4 的五个动作各做一次（此阶段允许给动作指令，因为测的是「会不会死档」不是「能不能想到」） |
| 填表归档 | 1 min | 当场填完 CSV 一行，录屏改名归档 |

### 2.4 S3 的五个定向动作（允许给指令）

折返回退 / 反向闭环 / 重复经过岔口 / 冲刺跨过触发点 / 倒地重开。
另外主持人自己走一遍：**所有必打敌人与出口都能靠实际步行到达**，不靠冲刺穿墙、不靠脚本瞬移。

### 2.5 需要准备

- 一台能双击打开 `file://` 页面的机器（无需联网、无需 Node、无需服务）。
- 录屏工具（系统自带即可），**只录游戏窗口，不录人脸、不录桌面个人信息**。
- 计时器、打印好的交接卡、本文件（主持人用）、CSV（主持人用）。
- 试玩者用**代号**（P01–P08），不记真实姓名。

## 3. 四条标准 → 可观测指标 → 判定阈值

> 阈值是按 8 人样本给的**建议值**；样本 6 人时按比例等比调整（如 5/8 → 4/6）。
> 这是人工判定口径，不是自动化断言，主持人需在备注里写明判断依据。

### S1 · 第一圈能自己走出来

| 观测项 | 判定 |
|---|---|
| 第一分钟内**主动**绕回并触发回扫 | 目标 **≥5/8**；主持人不得提示 |
| 能指出「波先从哪一段走」 | ≥5/8 说得出（含「说反了但能自圆其说」记「部分」） |
| 能说清「为什么打中了某个敌人」 | ≥4/8 说得出与站位 / 路线有关，而不是「运气」 |
| 首圈耗时 | 逐人记录秒数，取中位数；不设达标线，只作改版前后对比基线 |

**不通过信号**：多数人第一分钟只在原地射击 / 贴墙走 / 完全没意识到要绕回。

### S2 · 第二圈有理由换路

同一间房先保持相同布局，再**交换炮台位置或改变追兵起点**（主持人切换站位 A/B 实现），
观察玩家是否自己换走法。

| 观测项 | 判定 |
|---|---|
| 第二圈换路（反向 / 放弃短圈 / 改选长圈，任一） | 目标 **≥5/8** |
| 能说清换路理由 | ≥4/8，理由需与「敌人位置 / 路线长短 / 想打到谁」有关 |
| 只贴墙射击 | 记人数；若 **≥5/8** → 判不通过 |
| 一直跑同一个最短圈 | 记人数；若 **≥5/8** → 判不通过 |

**不通过时的改进顺序**（依《参赛改进与美术方向.md》§三 第 2 条）：
先改**岔路 → 敌人走位 → 回扫时机**，再扩内容；不要先加词条或美术。

### S3 · 绕路不能造成死档

| 观测项 | 判定 |
|---|---|
| 五个定向动作（折返回退 / 反向闭环 / 重复经过岔口 / 冲刺跨过触发点 / 倒地重开） | **0 卡死 / 0 无法继续**，逐项记「通过 / 卡住」 |
| 所有必打敌人可步行到达 | 是 |
| 出口可步行到达 | 是 |
| 出现「清不掉场 / 走不出去 / 重开后状态异常」 | **0 次**；出现即整轮不通过 |

> 关联：B1 的封闭墙圈死档已由队友用可达区域 BFS 修复，
> 总监独立复核 320 局 / 861 敌人 0 缺陷（见 `docs/acceptance.md` 附录）。
> S3 是**真人维度**的补验，自动化不能替代。

### S4 · 再扩成首层（本轮只做「准入判定」）

**如实标注**：三层长局、层末商店、存档恢复（M2 长局 + 存档）**尚未实施**，
本轮没有首层可测。因此 S4 本轮**不产出通关时间 / 商店取舍 / 存档恢复结果**，
只判定前置条件：

- 回扫在「一间普通房 + 一场首领战」中是否成立（S1 + S2 均通过，且 S3 为 0 死档）；
- 若成立 → 才进入 M2 实施（架构级，单独一轮）；
- 若不成立 → 回到 S2 的改进顺序，不扩层。

**禁止**用脚本战绩、理论模型或本包记录冒充「首层验收通过」。

## 4. 记录表字段（对应 `盲玩记录表.csv`）

一行一人，共 6–8 行。字段分五组：

- **基本信息**：编号 / 日期 / 代号 / 顺序位 / 站位 / 是否首次接触 / 窗口尺寸 / 录屏文件名
- **S1**：首圈耗时秒 / 主动绕回 / 触发回扫 / 指出波先走哪段 / 说明为何打中 / 第一分钟内完成
- **S2**：第二圈换路 / 换路类型 / 能说理由 / 只贴墙射击 / 一直跑最短圈 / 备注
- **S3**：折返回退 / 反向闭环 / 重复岔口 / 冲刺跨触发点 / 倒地重开 / 必打敌人可达 / 出口可达 / 死档次数
- **S4 与总评**：是否具备扩层准入 / 最困惑的点 / 最想再来一次的原因 / 主持人结论

可选热身轮字段（单房 A/B）单独列在 CSV 末尾，与主轮**不混算**。
字段值用「是 / 否 / 部分 / 通过 / 卡住 / 待定」，多值用中文分号「；」分隔（避免 CSV 逗号冲突）。
CSV 首行是表头，第二行是**示例行**（代号 `P00`，填表时删除或覆盖）。

### 回扫触发条件（引擎侧真实规则）

- 由角色**实际经过岔口和廊段**记录路径，**绕回起点时自动触发**。
- 至少经过**两条不同的连接路线**；原地转圈、单段来回**只更新印记，不触发**。
- 每个敌人在一次回扫中**最多受击一次**；上一道波走完后再记下一圈。
- 伤害只结算到波**实际经过的通道内**；折角靠墙体碰撞与现有敌弹逻辑表达。
- 地面三态：空白=未走、细线=已走、明亮短波=正在回扫。

### 词条与首领（设计稿，未全部实装，不要当作已实现去核对）

- 两个改变选路的词条：回扫出折角时**扩宽**（适合上廊）；
  路线达到指定距离时**提高回扫伤害**（适合走下廊的长圈）。
- 首领沿廊巡行，回扫命中巡行中的首领时**打破护盾**给输出窗口；
  二阶段更常改走中廊并提前预警。
- 长局口径：三层、层末存档续玩；每层至少两次回到熟悉的廊口，
  第二次换敌人站位或开放一条侧廊；层末商店决定留钱还是补给。
  **这些目前仍是设计，不是代码**。

### 单房 A/B 热身轮的已知脚本结论（仅用于对照，不要念给试玩者）

《单房自测记录.md》：8 种设置均两拨、击倒 9 只、结算胜利；

第二拨实际耗时、双方最早卡住的位置。
**预警顺序与脚本成功不能直接推出玩家会自然选择该打法。**
