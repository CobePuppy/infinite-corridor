## 0. 这轮要回答的问题

> 不靠脚本、不靠定向输入，**第一次玩的人**能不能自己看出
> 「按 `E` 定个起点，走出去再回到那里」这件事，并且第二圈愿意换个圈型？

自动化已证明的是：`tests/freewave.js` 23/23（含真实帧闭环、三层通关、护盾三态、渲染分流），
M12 新增 `tests/play.js` 5/5（**真实 WASD 输入，不瞬移**，11.8 秒走出 148 采样点、
面积 315814 的合法大圈并兑现，回扫波清掉整间房），M13 新增 `tests/loopcraft.js` 8/8
（量化出「连刷同型 5.74 伤害/秒 vs 换型序列 7.98 伤害/秒」）。
**这些不能证明玩家会自然选择该打法，也不能证明玩家看得懂「换型才涨倍率」**。
《单房自测记录.md》结尾原话仍成立：「预警顺序与脚本成功不能直接推出玩家会自然选择该打法。」
这正是本轮要补的空白 —— S2 现在**机制上**给了换路理由，但**可读性**仍要真人验证。

## 2. 主持人手册

### 2.1 人数与轮换

- **6–8 名初次玩家**，此前没看过《参赛改进与美术方向.md》、没看过任何证据截图、没听过机制讲解。
- 主轮统一用 **「自由回廊」** 入口。对照组改为**主题 A / B 各半**（如 8 人则 4/4），
  从当前四套主题里指定两套，**先跑 A 还是先跑 B 要在人与人之间交替**，避免顺序效应。
  注意：M11 已无固定「站位 A/B」，不要再用旧说法。
- 可选热身轮：**「经典回廊（旧版可回退）」**或单房试玩，用来接住
  《单房自测记录.md》的「真人待记」项。热身轮与主轮**分开记录、不混算**，
  且必须放在主轮**之后**（否则会教会玩家「沿预设廊道走」，污染主轮）。

### 2.2 三条铁律

1. **不剧透**：只念交接卡上那一句提示（「从哪儿出发，就回哪儿去。」），
   不解释「闭环」「面积」「回扫波」「地效」「凝滞」「护盾相位」「词条」，
   **也不说「换圈型才涨倍率」「同型会衰减」「小/中/大圈各有专属效果」**，
   不说面积门槛、不说圈型、不说子弹被削弱。
2. **不提示**：试玩中玩家卡住、问「怎么打」、走错路，主持人只回答「按你觉得对的来」，
   不指路、不示范、不代操作。卡满 **3 分钟**记一次「卡住」并继续观察，不救场。
   **例外**：若玩家连「`E` 定起点」都没发现，主持人**不主动说**，只在记录表
   `S1是否主动按E` 记「否」，并在追问阶段用中性问法确认（见 2.3）。
3. **先记录后看答案**：每人的记录表当场填完、录屏文件当场命名归档，
   **全部收齐之前**不要打开本文件第 8 节，也不要把数值 / 截图 / 定向结果给试玩者看。

### 2.3 单场时间轴（建议 12–15 分钟 / 人）

| 阶段 | 时长 | 主持人动作 |
|---|---|---|
| 交接 | 1 min | 给交接卡，念一遍提示与按键，确认能打开 `index.html` |
| 静默试玩 | 6–8 min | **全程不说话**，只记时间与行为；录屏从点「自由回廊」开始 |
| 追问 | 2–3 min | 按交接卡三个开放式问题逐条问，**原话记录**，不引导、不纠正。若玩家没主动提到「有一段光扫过去」，可追加一句中性追问：「刚才有没有注意到画面上有一段被点亮／扫过？它从哪边过来的？」——**只问现象，不解释机制、不说『回扫』二字** |
| 定向场景（S3） | 2–3 min | 追问结束后，再请玩家按 2.4 的五个动作各做一次（此阶段允许给动作指令，因为测的是「会不会死档 / 能不能恢复」，不是「能不能想到」） |
| 填表归档 | 1 min | 当场填完 CSV 一行，录屏改名归档 |

### 2.4 S3 的五个定向动作（允许给指令）

1. 故意绕一个**很小的圈**回到起点，看被拒后能否**自己继续绕大一点**再兑现（M12 修复点）；
2. **反向**绕同一块区域；
3. 走到一半**折返**再继续；
4. 先踩地面深色格、再踩浅色格，各待几秒；
5. **倒地重开**一局。

另外主持人自己走一遍：**所有敌人与出口都能靠实际步行到达**，不靠冲刺穿墙、不靠脚本瞬移。
自由房的四面墙 + 三处掩体位置见第 8 节答案卡。

### 2.5 需要准备

- 一台能双击打开 `file://` 页面的机器（无需联网、无需 Node、无需服务）。
- 录屏工具（系统自带即可），**只录游戏窗口，不录人脸、不录桌面个人信息**。
- 计时器、打印好的交接卡、本文件（主持人用）、CSV（主持人用）。
- 试玩者用**代号**（P01–P08），不记真实姓名。

## 3. 四条标准 → 可观测指标 → 判定阈值

> 阈值是按 8 人样本给的**建议值**；样本 6 人时按比例等比调整（如 5/8 → 4/6）。
> 这是人工判定口径，不是自动化断言，主持人需在备注里写明判断依据。

### S1 · 第一圈能自己走出来

| 观测项 | 判定 |
|---|---|
| 第一分钟内**主动**按 `E` 定起点 | 目标 **≥5/8**；主持人不得提示 |
| 起点由玩家自己选（不是被系统指定） | ≥5/8 能说清「我是在这儿按的」 |
| **回到起点**并触发兑现 | ≥5/8 |
| 能说清「为什么打中了某个敌人」 | ≥4/8 说得出与**站位 / 走的范围**有关，而不是「运气」 |
| 首圈耗时 | 逐人记录秒数，取中位数；不设达标线，只作改版前后对比基线 |

**不通过信号**：多数人第一分钟只在原地射击 / 贴墙走 / 完全没按 `E`。
若「没按 `E`」是主因，改进顺序是**先改教学可见性**（起点环、按键提示），不是加内容或改数值。

### S2 · 第二圈有理由换路

保持同一间房与同一主题，观察玩家是否自己换走法。自由回廊的「换路」不再是选另一条廊，
而是**换圈型**：扩大 / 缩小 / 改折点 / 换方向 / 绕掩体。

> **M13 口径更新（重要）**：v2 初版时这条标准在**数值上不成立** —— 一次性真实 WASD 探针
> 量化出小圈 **7.87** / 中圈 **6.16** / 大圈 **5.23** 伤害/秒，且 M11 连扫按次数累加，
> 连刷最小合法圈能滚到 **9.51** 伤害/秒，即「刷最小圈」就是最优解，玩家没有换路理由。
> M13 把**换圈型**做成唯一涨连扫倍率的途径（×1.0 → ×1.2 → ×1.4），重复同型逐次衰减
> 到 ×0.5，并给小 / 中 / 大圈各一个专属效果、折角圈附加穿透；复验为
> **换型序列 7.98 伤害/秒 > 连刷同型 5.74**。所以 S2 现在**机制层已给出换路理由**，
> 本轮要验的是**玩家看不看得懂**：LIVE 实时读数、兑现文字与 toast 是否足够让人自发改走法。
> 量化结论见 `tests/loopcraft.js` §J3 / §J4；它是**机制证据**，不是真人可读性结论。

| 观测项 | 判定 |
|---|---|
| 第二圈换走法（上述任一） | 目标 **≥5/8** |
| 能说清换路理由 | ≥4/8，理由需与「敌人位置 / 圈住的范围 / 想打到谁」有关 |
| 察觉「一直绕同一个圈越打越轻」 | 逐人记「是 / 否 / 部分」，**不设达标线**，作为 M13 衰减可读性的参考；若 ≥5/8 完全没察觉，记进「最困惑的点」 |
| 察觉「换一种圈有额外效果」（减 CD / 回血 / 破阵 / 圈边也扫） | 逐人记「是 / 否 / 部分」，不设达标线 |
| 只站桩射击 | 记人数；若 **≥5/8** → 判不通过 |
| 一直跑同一个圈 | 记人数；若 **≥5/8** → 判不通过 |
| 主动利用地效格 | 逐人记「是 / 否 / 部分」，不设达标线，作为区域层可读性参考 |

**不通过时的改进顺序**（依《参赛改进与美术方向.md》§三 第 2 条）：
先改**圈型收益的可读性 → 敌人布阵 → 兑现时机**，再扩内容；不要先加词条或美术。
M13 已把「收益」这一层补上，若仍不通过，优先排查 **LIVE 读数 / 兑现文字 / 同型衰减 toast
的可见性**，而不是再改数值。

### S3 · 手感可读且不会死档

| 观测项 | 判定 |
|---|---|
| 凝滞（世界变慢、自己全速）被察觉 | 逐人记「是 / 否 / 部分」，不设达标线 |
| 完美闪避 / 连段等级 / 正负地效被察觉 | 同上，作为可读性参考 |
| **小圈被拒后能自行恢复并兑现大圈** | 目标 **≥6/8**；这是 M12 修复点，失败即回到缺陷排查 |
| 五个定向动作（见 2.4） | **0 卡死 / 0 无法继续**，逐项记「通过 / 卡住」 |
| 所有敌人可步行到达 / 出口可达 | 是 |
| 出现「清不掉场 / 走不出去 / 重开后状态异常」 | **0 次**；出现即整轮不通过 |

> 关联：B1 的封闭墙圈死档已由队友用可达区域 BFS 修复（总监复核 320 局 / 861 敌人 0 缺陷）；
> M12 又修掉「出生点嵌在中央掩体内」与「小圈被拒后必须重按 `E`」两处本体缺陷，
> 见 `tests/play.js` §P1 / §P3。S3 是**真人维度**的补验，自动化不能替代。

### S4 · 首层与巡廊者（v2 改为「真的可测」）

v1 写「三层长局尚未实施，本轮没有首层可测」——**已失效**。M11 后三层九间 +
每层巡廊者 + 层末存档续玩全部实装，`tests/freewave.js` §H5 已用理想玩家跑通并清档。
因此 v2 判定的是**真人能不能走完、能不能读懂**：

| 观测项 | 判定 |
|---|---|
| 本轮到达的层 / 间 | 逐人如实记录，**不要求通关** |
| 是否遇到巡廊者 | 逐人记录；没遇到也要写明原因（死亡 / 时间到） |
| 能否看出护盾**闭合 → 崩解 → 重构**三态 | 目标 ≥4/8（M9 三态强视觉 + HUD 相位条） |
| 能否说出「这一相位要哪种圈」 | 目标 ≥3/8；说不出不算整轮不通过，但要记进「最困惑的点」 |
| 「从上次离开的圈接着走」续玩可恢复 | 至少 1 人成功（主持人可引导其主动退出再进入） |
| 死档次数 | **0 次** |

**禁止**用脚本战绩、理论模型或本包记录冒充「首层验收通过」，也**禁止**把
`tests/play.js` 的 11.8 秒当作真人单局时长——真人计时与重开率按
`docs/demo-90s.md` v4.1 §3.2 单独填写（目标 240s ± 30s，目前仍未真人验收）。

## 4. 记录表字段（对应 `盲玩记录表.csv`）

一行一人，共 6–8 行，41 列，字段分六组：

- **基本信息（8）**：编号 / 日期 / 代号 / 顺序位 / 对照组(主题A/B) / 是否首次接触 / 窗口尺寸 / 录屏文件名
- **S1 首圈（8）**：耗时秒 / 是否主动按E / 起点是否自选 / 是否回到起点兑现 / 首圈圈型 / 能否说出兑现与走位有关 / 第一分钟内完成 / 备注
- **S2 第二圈（7）**：是否换走法 / 换走法类型 / 能说清理由 / 是否一直站桩射击 / 是否重复同一圈 / 是否主动利用地效格 / 备注
- **S3 手感与容错（7）**：凝滞被察觉 / 完美闪避触发 / 连段等级被察觉 / 正负地效被察觉 / 小圈被拒后能否自行恢复 / 起点重设是否被理解 / 备注
- **S4 长局与护盾（6）**：抵达层间 / 是否遇巡廊者 / 能否看出护盾三态 / 能否说出相位圈型 / 存档续玩可用 / 死档次数
- **总评（5）**：最困惑的点 / 最想再来一次的原因 / 主持人结论 / S4首层判定 / 总备注

字段值用「是 / 否 / 部分 / 通过 / 卡住 / 待定」，多值用中文分号「；」分隔（避免 CSV 逗号冲突）。
CSV 首行是表头，第二行是**示例行**（代号 `P00`，填表时删除或覆盖）。

### 自由闭环链路（`src/core/freewave.js` + `engine.js updateFree`）

- 按 `E` → `FW.arm(f, p)` 记下 `origin` 并把 `path` 置为 `[origin]`；画面上出现
  **ORIGIN 起点环**与「回到此处兑现」。
- 每帧 `FW.record(f, p)`，与上一点距离 ≥ **`sampleGap = 14px`** 才采样。
- `FW.close(f, p)` 每帧尝试：要求**当前位置距起点 ≤ `closeRadius = 30px`**、
  **采样点 ≥ `minPoints = 8`**、**shoelace 面积 ≥ `minArea = 26000`**。
  面积不足返回 `{rejected:'area'}`，**不产出任何伤害**。
- **M12 修复**：拒绝分支原本 `FW.reset(f)` 后 `armed=false`，玩家松开 `E` 就再也画不了圈；
  现在 `reset` 后立即 `FW.arm(f, p)` 以当前位置重设起点，toast 改为
  「圈太小 · 起点已重设，绕大一点再回来」。`tests/play.js` §P3 验证「不重按 `E` 仍能兑现」。
- 合法闭环 → `FW.report()` → `waveFrom()` 生成**沿玩家路径逆行**的回扫波，
  只结算**多边形内**敌人；`distanceToPoly()` 给「长锋」词条提供圈边容差。
- 圈型由面积与折点数客观判定：`classify()` 分 `small / mid / big`（`areaMid=60000`、
  `areaBig=110000`），折点 ≥ `bendMin=3` 标「折角」；基础伤害 `24 / 30 / 52`。
- **M13 圈型策略**：`craft()` 以 `tag + (bent ? '+bent' : '')` 作圈型 key —— 首圈 ×1，
  **换型**逐段涨 `switchStep=0.20` 至上限 `switchCap=3` 段（即 ×1.4），
  **重复同型**按 `repeatDecay=0.80` 逐次衰减到 `repeatFloor=0.50`；
  26 秒窗口超时 `decayCraft()` 归零重新起算。`live()` 在走位中实时预估圈型 / 是否换型 /
  效果 / 穿透 / 面积点数是否达标，画面上写 `LIVE ... / 换型 ×N / 与上圈同型`。
- 主效果**由面积档决定**（折点只作附加穿透，否则矩形大圈天然带折点会永久吃掉「破阵」）：
  小圈 `quick` 减 55% 剩余攻击冷却 + 给 1 层连段；中圈 `mend` 回 5 HP；
  大圈 `breach` 额外给 `bigCharge=1` 点护盾蓄势并把凝滞延长 `bigStall=0.22s`；
  折角圈 `pierce` 让回扫波多 `bentReach=32px` 圈边容差。
- **M13 顺带修复**：`chrono.stall()` 原为直接赋值 0.35s，大圈兑现后同一帧回扫波命中敌人
  会再调一次把它覆盖回去；现改为 `Math.max(c.stall, stallTime)`，且大圈延长也用 max 而非
  `+=`，连续大圈不会无限叠时。`tests/loopcraft.js` §J4 用真实帧断言这一点。
