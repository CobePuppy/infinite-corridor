## v3 相对 v2 的改动（如实在案）

v2 是按**旧「经典射击」主模式**写的：6 套降级模板 / 3–8 房 / 24 词条 / Boss 半血切 P2。
M7 把主模式换成「回廊长局」、M8 重做美术、M9 加入多相位护盾、M10 补上闭环兑现演出后，
整份分镜的玩法名词已全部失效，故 v3 按当前主模式**整体重剪**。

| 项 | v2（经典射击） | v3（回廊长局 · 当前主模式） | 依据 |
|---|---|---|---|
| 单局结构 | 3–8 房 + 1 首领 | **3 层 × 3 间 + 每层巡廊首领**，层末写 `corridor.loop.save.v1` | M7 `core/loop.js` `plan()` |
| 核心操作 | 站桩射击、清房进出口 | **绕一圈，从另一侧回击**：沿廊道实时绕行，闭环后沿原路逆向扫回 | 队友《参赛改进与美术方向.md》§一 |
| 主输出 | 子弹 | **闭环回扫**；长局子弹伤害 ×0.34，只在护盾窗口全额生效 | `BALANCE.loop.bulletMul` |
| 构筑 | 24 词条 / 二选一 / 每 3 次三选一 | **独立 `LOOP` 路线词条池** + 破盾 4 条；「下一圈怎么走」三选一 | M7 / M9 |
| 首领 | 半血切 P2 弹幕 | **多相位护盾**：闭合 → 崩解 → 全额输出窗口 → 重构 → 下一相位；相位要求不同圈型 | M9 |
| 视觉 | 四套色板 + 背景构图 | **深蓝测绘图 / 夜航档案**：图廓刻度、琥珀金唯一高亮、闭环兑现光带、护盾三态 | M8 / M10 |
| 界面读数 | 房间数 / 连击 / 协同 | 层级 + 廊型 + 护盾相位条 + **连扫蓄势条**（倍率与 26 秒窗口） | M9 / M10 |

**不变的两条口径**：

1. **90 秒 = 成片长度**，与单局长度无关；过程全部跳剪，只取爆点。
2. **单局目标 240s ± 30s（210–270s）**，来自用户「单条命通关应该在 4 分钟左右」。
   ⚠️ 该口径针对**真人计时**，且是在旧经典长局下定的；**回廊长局三层九间的真人计时尚未做**，
   v3 不把任何自动模拟数字冒充成结论。见 §3。

## 1. 两局「明显不同」的设计与判据

§8 只要求「录到两局不同关卡」，**不要求录完整过程**。回廊长局的差异来自
`plan(seed)` 的确定性编排与主题切换，不来自「房间数」：

| 维度 | 第一局（建议） | 第二局（建议） | 成片里的交代方式 |
|---|---|---|---|
| 主题 id / 名称 | `geometry` / 抽象几何 | `oldtown` / 旧城 | HUD 主题标签特写 + 四宫格同框 |
| 层 / 间进度 | 第 1 层 第 1 间 | 第 2 层 第 2 间（用「继续回廊」续玩进入） | HUD 层级读数同框特写 |
| 廊型 | `fork` / 三岔廊（上廊直、下廊长） | `deepwell` / 深井廊（下廊更深、折点不同） | 廊道地面 + 房间名 toast 特写 |
| 首领相位圈型 | 相位 1「任意闭环」→ 相位 2「折角圈」 | 相位 2「折角圈」→ 相位 3「长圈」 | 护盾条相位标签同框 |
| LOOP 词条组合 | 短圈聚锋 + 折角扩散 + 连扫 | 长程蓄力 + 破阵 + 过载回扫 | 第 3 段词条卡特写 |
| 结局 | 通关或死亡 | 另一结局（两种都要覆盖） | 结算页 |

> **四项硬差异**（主题 / 层间进度 / 廊型 / 词条组合）须在成片中**可辨认**，
> 用 HUD 特写同框 + 数据卡即可满足 §8 第 7 条，不录完整过程。
> `plan(seed)` 是确定性编排，同一 seed 可复现；录制时用新 seed 或续玩存档取到不同层间。

## 3. §8 要求的记录表：重开率与单局时长

### 3.1 口径定义（v3 修订）

- **单局时长**：从 `runStart` 到 `runEnd` 的 `elapsed`（结算页「存活 x.xs」）。
  目标 **240s ± 30s，即 210–270s**；倍速 / 跳剪演示片段**不计入**，本表只登记真实试玩局。
- **主模式口径**：一次「局」= 从首页「回廊长局」开局，到通关第 3 层或死亡；
  「继续回廊」续玩属于**同一局**，不另计一局。
- **结局**：`死亡` 或 `通关`（结算页标题「这次停在了这里」/「走廊走到了尽头」）。
- **是否重开**：该局结束后是否点「再来一局」立即开始下一局。
- **重开率** = `重开次数 ÷ 总局数`（最后一局通常为「否」，不算重开）。无强制阈值，如实登记。
- 采样建议：连续试玩 ≥ 5 局，覆盖「死亡」与「通关」、至少一次切主题重开，
  **且至少覆盖第 1 层与第 2 层**（续玩链路要在样本里出现）。

### 3.4 为什么 v3 删掉了 v2 的理论模型表（如实说明）

v2 §3.4 用 `calibrate()` 按「敌人 HP ÷ 子弹 DPS × 命中率」外推 6 / 7 / 8 房时长。
**这个模型对当前主模式已不成立**：回廊长局的主输出是闭环回扫（波伤 34，长/短圈 48–54，
连扫最高 ×1.3，护盾窗口还有 ×2.2），子弹被压到 ×0.34 且只在窗口全额生效；
敌人 HP 不再是决定时长的唯一变量，**绕行路径长度、圈型选择、护盾相位门槛**才是。

因此 v3 **不放一张看似精确、实则失真的外推表**。4 分钟是否达成，以 §3.2 真人计时为准；
若真人实测偏长，校准旋钮集中在 `src/core/perks.js` 的
`BALANCE.loop`（`damage` / `longDamage` / `shortDamage` / `shield.baseNeed` / `shield.baseWindow`），
**不得直接改 `engine.js` 的手感常量**。

> 自动化脚本只能证明链路成立、基线未回归，**不能**代替手感与时长采样，故 §3.2 留空待录。
